Every Livewire component and UI component explained — plus a step-by-step guide to adding new features.

Livewire Components — Overview

Every Livewire page is made of exactly two files that always live side by side:

structureThe two-file Livewire pattern 
// 1. PHP Class — the LOGIC (state, methods, queries)
app/Livewire/SuperAdmin/Dashboard/DashboardPage.php

// 2. Blade View — the HTML (reads from the PHP class)
resources/views/livewire/super-admin/dashboard/dashboard-page.blade.php

Key attributes used on every Livewire page component:

Attribute Where What it does
#[Layout(...)] PHP class Wraps the component in a layout shell (sidebar + header)
#[Title(...)] PHP class Sets the HTML <title> and the header title prop
#[Url] PHP property Syncs property to URL query string (survives refresh/share)
#[Validate(...)] PHP property Validation rule attached directly to a property

DashboardPage

DashboardPage app/Livewire/SuperAdmin/Dashboard/DashboardPage.php

The main landing page after login. Uses computed properties — properties prefixed with get and suffixed with Property that are lazily evaluated and cached per request.

php 
// Computed property — called as $this->stats in PHP, $stats in Blade
public function getStatsProperty(): array
{
    return [
        'total_businesses'   => Business::count(),
        'active_businesses'  => Business::where('status', 'active')->count(),
        'total_staff'        => User::whereHas('roles', ...)->count(),
        'pending_businesses' => Business::where('status', 'pending')->count(),
    ];
}

// In render(), pass to Blade view as variables
public function render()
{
    return view('livewire.super-admin.dashboard.dashboard-page', [
        'stats'             => $this->stats,
        'recentBusinesses'  => $this->recentBusinesses,
        'businessTypeStats' => $this->businessTypeStats,
    ]);
}

View file dashboard-page.blade.php renders:

  • 4-column stats grid using <x-ui.stats-card>
  • Recent businesses table using <x-ui.card> + <x-ui.table>
  • Business type distribution with progress bars + emoji icons
  • Quick Actions panel linking to other pages

BusinessListing

BusinessListing app/Livewire/SuperAdmin/Businesses/BusinessListing.php

Paginated, searchable, filterable, and sortable business table with inline status changes and delete confirmation.

Public Properties

$search#[Url]
Synced to ?q= in URL. Searches name, email, city. Debounced 300ms in view.
$statusFilter#[Url]
Synced to ?statusFilter=. Filters by active | inactive | pending | suspended.
$typeFilter#[Url]
Synced to ?typeFilter=. Filters by cafe | hotel | restaurant | bar | other.
$sortBy
Column to sort by. Default: created_at.
$sortDir
Sort direction. Default: desc. Toggles asc↔desc on repeated click.
$showDeleteModal
Controls delete confirmation modal visibility.
$deletingId / $deletingName
Stores which business is being deleted (shown in modal text).

Key Methods

Method What it does
sort($column) Toggles sortDir if same column, otherwise sets new column + asc
confirmDelete($id) Loads business name, sets deletingId, shows modal
deleteBusiness() SoftDeletes the business, hides modal, flashes success
updateStatus($id, $status) Inline status update — triggered by Alpine dropdown in table row
updatedSearch() Lifecycle hook → resets pagination to page 1 on filter change
Why #[Url] on filters?

URL-synced filters mean users can bookmark a filtered view, share the URL, or refresh without losing their place. The URL shows ?q=cafe&statusFilter=active automatically.

BusinessCreation

BusinessCreation app/Livewire/SuperAdmin/Businesses/BusinessCreation.php

Multi-section creation form. Validation rules live directly on the properties using #[Validate] (Livewire 4 syntax — NOT the old #[Rule]).

phpValidation on properties (Livewire 4 pattern) 
#[Validate('required|min:2|max:100')]
public string $name = '';

#[Validate('required|in:cafe,hotel,restaurant,bar,other')]
public string $type = 'cafe';

#[Validate('nullable|email|max:100')]
public string $email = '';
phpSave method with SPA redirect 
public function save(): void
{
    $this->validate(); // Validates all #[Validate] properties at once

    Business::create([...]);

    session()->flash('success', 'Business created successfully.');

    // navigate: true = SPA navigation (no full page reload)
    $this->redirect(route('super-admin.businesses.index'), navigate: true);
}

The view uses three <x-ui.card> sections: Business Info, Contact Details, and Subscription. The subscription section uses CSS peer pattern for radio card buttons.

StaffManagement

StaffManagement app/Livewire/SuperAdmin/Staff/StaffManagement.php

Staff table with create modal, delete confirm modal, role filter, status toggle. Protects super admin accounts from modification.

Create Staff Flow

php 
// Form fields prefixed with "new" to avoid naming collision
public string $newName       = '';
public string $newEmail      = '';
public string $newPassword   = '';
public string $newRole       = 'staff';
public ?int   $newBusinessId = null;

public function openCreateModal(): void
{
    // resetExcept keeps filter state, clears form fields
    $this->resetExcept(['search', 'roleFilter', 'statusFilter']);
    $this->showCreateModal = true;
}

public function createStaff(): void
{
    $this->validate();

    $user = User::create([
        'name'        => $this->newName,
        'email'       => $this->newEmail,
        'password'    => Hash::make($this->newPassword),
        'business_id' => $this->newBusinessId ?: null,
        'status'      => 'active',
    ]);
    $user->assignRole($this->newRole); // Spatie role assignment
    ...
}
Super Admin Protection

confirmDelete() and toggleStatus() both check !$user->isSuperAdmin() before proceeding. Super admin accounts show "Protected" instead of action buttons in the UI.

RolesPermissions

RolesPermissions app/Livewire/SuperAdmin/Roles/RolesPermissions.php

Two-panel layout: role list on the left, permission toggle grid on the right. Clicking a permission checkbox calls the server immediately (no save button needed).

php 
// Permissions grouped by prefix in render()
$permissions = Permission::orderBy('name')->get()->groupBy(function ($p) {
    return explode('.', $p->name)[0]; // 'business.view' → 'business'
});

// Toggle a permission on/off
public function togglePermission(int $roleId, string $permissionName): void
{
    $role = Role::findOrFail($roleId);

    if ($role->name === 'super_admin') {
        session()->flash('error', 'Super Admin cannot be modified.');
        return;
    }

    if ($role->hasPermissionTo($permissionName)) {
        $role->revokePermissionTo($permissionName);
    } else {
        $role->givePermissionTo($permissionName);
    }
}

PlatformSettings

PlatformSettings app/Livewire/SuperAdmin/Settings/PlatformSettings.php

Tabbed settings panel with 4 tabs: General, Features, Billing, Security. Uses PlatformSetting model's static helpers to read/write a key-value database table.

phpmount() — reads from DB into properties 
public function mount(): void
{
    // PlatformSetting::get('key', 'default') reads from platform_settings table
    $this->platformName  = PlatformSetting::get('platform_name', 'BrewFlow');
    $this->platformEmail = PlatformSetting::get('platform_email', 'admin@brewflow.com');
    $this->enableRegistration = (bool) PlatformSetting::get('enable_registration', true);
    // ...and so on for all settings
}
phpsaveFeatures() — feature toggle pattern 
public function saveFeatures(): void
{
    // Booleans stored as '1'/'0' strings in DB, cast back on read
    PlatformSetting::set('enable_registration', $this->enableRegistration ? '1' : '0', 'features', 'boolean');
    PlatformSetting::set('maintenance_mode',    $this->maintenanceMode ? '1' : '0', 'features', 'boolean');

    session()->flash('success', 'Feature settings saved.');
}

// In view, toggle uses wire:click="$toggle('propertyName')"
// <button wire:click="$toggle('enableRegistration')">

The $activeTab property controls which section panel is shown. Tab buttons use wire:click="$set('activeTab', 'general')".

UI Component Reference

All components live in resources/views/components/ui/ and are called with <x-ui.component-name>.

<x-ui.stats-card>ui/stats-card.blade.php
label*
Caption text below the number (e.g. "Total Businesses")
value*
The big number displayed. Use :value="$count" for dynamic values.
color
amber (default) | blue | green | red | purple
trend
Text shown below value (e.g. "+12%" or "3 new")
:trendUp
true = green up arrow | false = red down arrow
#icon (slot)*
SVG icon rendered inside the colored square. Use class="w-6 h-6 text-white".
blade 
<x-ui.stats-card
    label="Total Businesses"
    :value="$stats['total_businesses']"
    color="amber"
    trend="+12%"
    :trendUp="true"
>
    <x-slot:icon><svg class="w-6 h-6 text-white">...</svg></x-slot:icon>
</x-ui.stats-card>
<x-ui.card>ui/card.blade.php
title
Card header title. Can be a string or a slot (for custom HTML like badges).
description
Subtitle shown below title in the header.
:padding
true (default) = adds p-6 to body. false = no padding (for flush tables).
#action (slot)
Content shown in top-right of card header (buttons, links).
blade 
<x-ui.card title="Recent Businesses" description="Latest registrations">
    <x-slot:action>
        <x-ui.button size="sm" variant="outline">View all</x-ui.button>
    </x-slot:action>
    {{-- content here --}}
</x-ui.card>
<x-ui.badge>ui/badge.blade.php
color
green | red | yellow | amber | blue | gray | purple | orange

<x-ui.badge color="green">Active</x-ui.badge>

primary (default) | secondary | danger | outline | ghost | success
size
xs | sm | md (default) | lg
type
button (default) | submit | reset
href
If provided, renders as <a> tag instead of <button>

Common Patterns

Flash Messages with Auto-Dismiss

bladePattern used on all listing pages 
{{-- In Blade view: auto-removes after 4 seconds via Alpine --}}
@if(session('success'))
    <div x-data x-init="setTimeout(() => $el.remove(), 4000)"
         class="p-4 bg-emerald-50 border border-emerald-200 rounded-xl">
        {{ session('success') }}
    </div>
@endif

// In PHP component:
session()->flash('success', 'Business created!');

Livewire Loading States

blade 
<button wire:click="save" wire:loading.attr="disabled">
    <svg wire:loading wire:target="save" class="animate-spin w-4 h-4">...</svg>
    <span wire:loading.remove wire:target="save">Save</span>
    <span wire:loading wire:target="save">Saving...</span>
</button>
{{-- wire:target scopes loading to only the "save" action --}}

Soft Deletes — Recover Data

php 
// Standard delete (soft — sets deleted_at, stays in DB)
Business::findOrFail($id)->delete();

// Restore a soft-deleted record
Business::withTrashed()->find($id)->restore();

// Permanently delete (cannot undo)
Business::withTrashed()->find($id)->forceDelete();

// Query including soft-deleted records
Business::withTrashed()->get();

PlatformSetting Read/Write

phpapp/Models/PlatformSetting.php 
// Read (returns typed value, not always string)
$name          = PlatformSetting::get('platform_name', 'BrewFlow');  // string
$isEnabled     = PlatformSetting::get('enable_registration', true); // bool

// Write (upsert — creates or updates)

PlatformSetting::set('enable_registration', '1', 'features', 'boolean');
PlatformSetting::set('trial_days', '14', 'billing', 'integer');

Adding a New Page

Follow these 5 steps to add a new Reports page. The same pattern applies to any new section.

1
Create the Livewire component class
shell 
php artisan make:livewire SuperAdmin/Reports/ReportsPage
# Creates: app/Livewire/SuperAdmin/Reports/ReportsPage.php
# Creates: resources/views/livewire/super-admin/reports/reports-page.blade.php
2
Edit the PHP class — add Layout + Title + your logic
phpapp/Livewire/SuperAdmin/Reports/ReportsPage.php 
#[Layout('components.layouts.super-admin')]
#[Title('Reports')]
class ReportsPage extends Component
{
    public function render()
    {
        return view('livewire.super-admin.reports.reports-page');
    }
}
3
Edit the Blade view — use the design system components
bladeresources/views/livewire/super-admin/reports/reports-page.blade.php 
<div>
    <x-super-admin.breadcrumb :items="[['label' => 'Reports']]"/>

    <div class="mb-6">
        <h2 class="text-xl font-bold text-slate-800">Reports</h2>
    </div>

    <x-ui.card title="Sales Overview">
        {{-- your content here --}}
    </x-ui.card>
</div>
4
Add the route inside the protected middleware group
phproutes/web.php — inside middleware(['auth', 'super_admin']) group 
use App\Livewire\SuperAdmin\Reports\ReportsPage;

Route::get('/reports', ReportsPage::class)->name('reports.index');
5
Add the nav item to the sidebar
bladeresources/views/components/super-admin/sidebar.blade.php 
{{-- Add under Configuration section or create a new section --}}
<x-super-admin.nav-item
    route="super-admin.reports.index"
    label="Reports"
    icon="chart-bar"
/>

Available icons: chart-bar, building, users, shield, cog. Add new icons in nav-item.blade.php.

That's all 5 steps!

The new page is automatically protected by the same auth + super_admin middleware. The sidebar highlights it as active based on the route name. The layout, breadcrumb, and all UI components are ready to use.
